## 事实核对

- 用户目标保持为原币记账、分币种统计，并用一个汇总币种查看整体资产负债。
- 正式术语保持为列报货币，界面建议名称保持为汇总币种。
- 一份数据库代表一个家庭共享预算空间；两位家庭成员的同币种预算账户共同使用一份 `Ready to Assign`，账户和流水仍分别保存。
- 首版内置支持目录已经更新为 CNY、USD、SGD、CAD、EUR、GBP、JPY。用户日常使用 CNY、USD、SGD，偶尔使用 JPY。
- YNAB 当前官方口径保持为每种币种使用独立 plan，换汇分别记录转出与转入。
- YNAB 投资口径保持为预算外跟踪账户，进入净资产并排除在日常收支之外。
- 当前代码仍只有全局货币符号，没有账户币种、汇率或不同金额的跨币种转账。
- 主方案把 YNAB 的币种隔离放进一个本地数据库，并增加原产品没有的统一净资产列报层。
- Frankfurter ECB Adapter 是首版默认自动源，参考汇率只用于估值，真实换汇金额始终以银行两端入账为准。
- [Frankfurter v2 官方文档](https://frankfurter.dev/)确认可以用 `providers=ECB` 固定数据源；[ECB 当前参考汇率列表](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)包含 SGD，也覆盖首版其余六种货币。
- FX Module 通过厂商无关的 Provider Interface 接入自动源。Adapter 输出规范化记录并运行共享契约测试，替换 Provider 不要求修改报表或迁移财务数据。
- 用户已经确认从内置目录启用币种。新家庭默认启用 CNY、USD、SGD、JPY、EUR，CAD 和 GBP 保持可选，目录外币种不由用户自行定义。
- 测试计划沿用仓库现有 Vitest、真实临时 SQLite、随机本机端口 Express 和 Testing Library，不假设已经安装 Supertest 或浏览器 E2E 框架。
- 2026-08-30 在本机 Node 25.8.1 下重跑现有套件，解除沙箱端口限制后的结果为 242 个测试通过、6 个既有 BudgetPage 测试因 `localStorage.clear is not a function` 失败。多币种实现前需要用 CI 同款 Node 20 建立绿色基线。
- 本轮只产出方案文件，没有修改业务代码、数据库或用户数据。

以上事实全部对齐。

## 主线回读

主线是一句话：一份家庭预算按币种隔离记账和分配，所有账户只在净资产报表中按列报货币换算汇总。

主方案各节都服务于这条主线。决策记录保存已经确认的范围和默认启用规则，当前没有待选分支。测试计划把每项财务规则落到可复算的自动化测试或手工验收。里程碑从绿色基线开始，依次交付金额基础、数据迁移、各币种预算、统一写入、汇率、净资产、投资、AI/IM 和发布验收，可以直接驱动逐项 TDD 实现和检查点提交。
