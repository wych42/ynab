# 多币种页面重构：验收用例脑暴

> 日期：2026-09-05
>
> 范围：页面币种职责重构。只读核对代码、现有测试和三份产品文件后写出。不改产品代码，也不改既有方案。
> 口径来源：`ui-product-intent.md` 的页面规则。当前仓库仍是旧交互，不能把这份清单当成已经交付。

## 这份清单怎么来的

我没有沿用协调者的结论。先读产品意图、未决细节、独立审阅和主方案，再对照当前前后端和测试。下面这些是仓库里现在真实存在的行为，也是这轮页面重构必须翻过去的基线：

- 路由是 hash。`App.tsx` 用 `window.location.hash`，预算、报表、账户都没有币种查询参数。交易页只解析 `filter=uncategorized`。
- 预算账本存在 `localStorage` 键 `activeBudgetCurrency`，再经由 `store.tsx` 的 `activeCurrency` 喂给预算页和原币报表。侧栏底部仍有全局选择器。
- 账户页、交易页已经按账户币种格式化，不读 `activeCurrency`。新建账户下拉却列出整份内置目录，服务端 `createAccountRecord` 会在写入时隐式 `enableBuiltInCurrency`。
- 账户详情对已有流水的账户仍提供可编辑币种下拉；外币消费表单无条件展示，选项包含账户自身币种。
- 交易页次级金额没有「账户入账 / 商户计价」或「转出 / 入账」标签。批量栏只显示笔数，目前没有跨币种合计，这个空白必须锁死。
- 报表只有「原币收支 / 统一净资产」两个本地 tab。原币视图跟活动币种走，并且把「当前净值」和收支画在同一页。`GET /api/reports/overview` 仍要求单个 `currency`，并不是跨币种摘要。投资只有账户详情里的原币摘要，没有报表入口。
- 设置页文案仍是「汇总币种」。只能启用 CAD/GBP，没有停用。汇率区直接展示 `manual`、`frankfurter_ecb` 和完整缓存列表。
- 预算写接口没有 `expectedRevision`。仓库里的 `409` 目前只用于迁移锁定和部分 FX 冲突，不是家庭并发预算冲突。
- 现有页面测试把旧交互写进了断言：侧栏必须有 `sidebar_budgetCurrency`，预算页和原币报表必须跟 `activeCurrency` 走。实现新交互时，这些测试要改写，不能靠它们保持绿灯来宣称页面已交付。

已发布的金额、预算隔离、转账双腿、缺汇率隐藏总数、JPY 精度，仍然是回归面。它们不能替代下面这些页面职责用例。

## 共用夹具

金额按界面显示值写。自动化时再转最小货币单位。估值日固定 `2026-09-04`。家庭时区 `Asia/Shanghai`。净资产默认币种 `CNY`。已启用：`CNY, USD, SGD, EUR, JPY`。未启用：`CAD, GBP`。

| 账户 | 币种 | 类型 | 余额 | 说明 |
| --- | --- | --- | ---: | --- |
| 家庭日常 | CNY | 预算内支票 | 100,000.00 | 有分配和目标 |
| 中信信用卡 | CNY | 预算内信用卡 | -5,000.00 | 有流水 |
| 星展日常 | SGD | 预算内支票 | 5,000.00 | 本月有工资 |
| 美元卡 | USD | 预算内信用卡 | -22.00 | 商户计价 EUR 20.00，入账 -22.00 USD |
| 先锋券商 | USD | 预算外投资 | 10,000.00 | 有估值调整 |
| 日元现金 | JPY | 预算内现金 | 100,000 | 零位小数 |
| 欧元备用 | EUR | 预算内支票 | 0.00 | 无非期初流水，可改币种；零活动 |
| 空账本 GBP | — | 无账户 | — | 用例里临时启用后再停用 |

固定流水：`100.00 SGD` 转到 `550.00 CNY`；餐饮分类在 CNY 和 SGD 各有不同分配。界面语言默认中文，双语用例再切英文。

自动化层级约定：

- **模块**：Money / Ledger / FX / Reports / Budget 的公开函数。
- **HTTP**：Express 契约，含 4xx 和 revision。
- **组件**：jsdom + Testing Library，锁控件、文案、请求参数、空状态。
- **浏览器**：真实 hash、前进后退、`replace`、双视口。仓库现在没有 Playwright，P0 浏览器项在引入 E2E 前必须手工跑，并留下步骤。
- **双会话**：两个浏览器配置或两个 origin 打同一 SQLite，专门覆盖 409。

## 现有方案还漏掉的测试维度

`test-plan.md` 覆盖的是已落地的金额、迁移、隔离、转账、FX、单币种报表和投资账户摘要。它明确把 Playwright 排除在首版门槛外，手工清单也还在旧导航上：侧栏切币种、原币收支跟活动币种走、设置里叫汇总币种。页面重构如果只加几条组件测试，会漏掉下面这些。

**路由和历史。** 产品写了 URL，测试计划没有 hash 查询、`replace` 回退、前进后退死循环、多标签各看各的账本、无痕窗口打开复制链接。现有 `App.tsx` 账户详情正则是精确匹配，查询参数会把详情打回列表，这个回归点方案里没写。

**停用。** 测试计划只启用 CAD/GBP。没有停用、没有「使用中」、没有停用后旧链接。服务端今天甚至没有停用接口，HTTP 契约要从红灯写起。

**并发。** 测试计划用两个 CNY 账户证明家庭共享待分配，没有乐观并发。`409` 现在被迁移锁占用，预算冲突的状态码、响应体、前端并排展示都是新面。

**跨币种摘要 API。** `GET /api/reports/overview` 名字像总览，实际要单个 `currency`。新的全部视图如果误用它，会做成「再画一个单币种页」。需要新的无币种参数契约，并断言响应按币种分区、不可相加。

**投资作为报表。** 现有测试锁的是账户详情摘要，没有第三个报表入口、同币种小计、异币不相加、从投资跳净资产。

**控件角色。** 方案验收句有「不要裸 CNY」，但没有读屏、`aria-live`、焦点、触屏下的行内操作、375 宽标题区选择器。独立审阅也没做无障碍。

**隐式启用的服务端面。** 页面就算只列出已启用币种，`createAccountRecord` 和 `changeAccountCurrency` 仍会 `enableBuiltInCurrency`。只测 UI 下拉不够，HTTP 必须拒绝未启用代码。

**原始消费目录。** 测试计划有 EUR 原始金额，没有「GBP 未启用仍可填」和「选项排除账户币种」。

**本地存储残留。** 产品禁止净资产临时值写 sessionStorage / localStorage。预算最近账本却仍要用本机存储做无参数回退。测试得写明哪个键还可以留、哪个键写了就算失败。

**旧组件断言。** `Sidebar.currency.test.tsx`、`BudgetPage.currency.test.tsx`、`ReportsPage.currency.test.tsx` 会在重构时变红。测试计划把它们当成已完成页面覆盖，没有把「改写旧断言」列进发布门槛。不改写就会出现两种失败：实现新交互而 CI 红，或为了绿着而把全局选择器留着。

**助手。** 产品意图要求按币种分组回答支出、折算时声明日期和来源。现有 AI 测试覆盖类型化写入和确认卡，没有「这个月花了多少」这种问法的展示契约。

**月份和估值日。** 预算月份仍可以只活在页内；净资产估值日必须进 URL。两者不一致，容易有人把月份也塞进存储，或把估值日只放 React state。需要对「哪些状态进 URL」做一张对照表测试。

建议落地时：模块和 HTTP 继续守金额；组件测试改写旧 IA 并覆盖本文件 P0；浏览器至少手工跑 URL、后退、replace 回退、双会话 409、375/1280、中英；有重复路由回归再加 Playwright，专门打 hash 历史，不必把全部金额场景搬进 E2E。
