# 页面产品意图写作检查

## 事实核对

- 首版内置支持 CNY、USD、SGD、CAD、EUR、GBP、JPY；新家庭默认启用 CNY、USD、SGD、JPY、EUR。
- 每个账户只有一个账户币种；预算金额按币种账本隔离；家庭净资产才按列报货币换算。
- 当前线上版本仍有侧栏活动币种选择器，收支报表目前只显示一个币种。新文档描述的是待实施页面重构。
- 页面重构没有改变汇率用途：参考汇率只用于资产负债估值，实际换汇保留银行两端真实金额。
- 页面重构没有改变家庭模型：同一币种仍只有一份共享预算账本，设备上的当前页面选择不写入家庭共享状态。
- 已启用币种严格限制账户和预算账本；消费原始币种只保存商户计价信息，可以使用内置支持目录中尚未启用的代码。
- 两台设备对共享预算的并发写入需要币种账本级 revision，所有影响预算读模型的写入都推进版本。

以上关系与既有多币种方案一致。

## 本次调整

- 把容易混淆的“币种选择”拆成账户币种、消费原始币种、预算账本币种、汇总币种和启用币种。
- 删除跨页面的活动币种概念，把预算账本、收支筛选和净资产汇总控件放回各自页面。
- 把“原币收支”改为“收支（按币种）”，明确全部币种摘要和单币种详细视图的区别。
- 把页面选择写进 URL，补齐旧链接引用停用或不受支持币种时的回退行为。
- 补充共享分类提示、预算并发冲突、空币种账本、锁定账户币种和双金额语义。
- 将现有页面与目标设计之间的差距写进主方案，避免把新设计误报成已上线功能。
- 由不继承当前对话的独立 subagent 体验正式页面、核对代码并审阅方案。双方经过三轮分歧收敛后，独立复核结论为“无阻塞项”。
- 由另一名全新 subagent 从验收视角整理 55 条对抗式用例；实施方案再按服务端契约、页面局部状态、三类报表和冲突收口拆成四张顺序 ticket。

## 机械扫描

对 `ui-product-intent.md`、`ui-open-questions.md`、`ui-independent-review.md`、`ui-acceptance-brainstorm.md`、`ui-implementation-plan.md`、`ui-acceptance-plan.md`、四张 ticket、`ui-writing-review.md` 和 `plan.md` 执行章节序号、翻案句式、空泛元话语和中文正文半角标点扫描，四类结果均为零命中。`git diff --check` 通过。

## 主线反思

主线是：每个币种控件都要紧贴当前任务，并清楚说明它控制的是记账、预算、筛选还是折算。

逐页规则都在解释这条主线，没有额外引入新的货币模型。相较原方案，页面作用范围更清楚，也补上了当前实现与目标设计的边界。
