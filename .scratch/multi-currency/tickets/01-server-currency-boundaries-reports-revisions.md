# Ticket 01：服务端币种边界、报表接口与 revision

## 目标

建立后续页面可以依赖的服务端契约：账户只能使用已启用币种，空币种账本可以安全停用；收支总览、收支详情和投资总览有稳定接口；预算账本和共享分类结构支持乐观并发。

## 必须先写的失败测试

- 账户创建和空账户改币种提交未启用 CAD 时返回 `currency_not_enabled`，且不创建 CAD 账本。
- 原始消费币种允许未启用 GBP，但拒绝与账户币种相同的代码，不改变启用集合。
- 停用空 CAD 成功；有账户、交易、分配、目标或作为净资产默认值时，分别返回稳定错误和使用原因。
- 收支总览按账户币种分区，没有跨币种总计；详情延续现有预算内现金流口径并排除转账、投资投入取回和估值调整。
- 投资总览按币种和账户返回当前估值、变化、投入、取回、净投入和最近估值日，不返回收益率。
- 预算读取返回 `revision` 与 `categoryRevision`。覆盖分配、移动、补超支、自动分配、复制上月、目标、预算内账户创建/关闭、交易新增/编辑/删除/清算/分类、对账和转账的 revision 参数化测试。
- 过期 revision 原子返回 409 且业务数据不变；不同币种写入互不冲突；跨币种转账同时校验并推进两个账本；共享分类写入只推进 `categoryRevision`。

## 实现约束

- 新 migration 只增加 revision 所需字段或表，不改写已有金额和币种。
- 把 revision 校验、推进和冲突响应集中到一个明确模块，不在每条路由复制 SQL。
- 对多币种转账和影响多张表的写入使用现有 SQLite transaction 边界；校验与推进必须与业务写入原子完成。
- 保留旧报表接口一个兼容周期可以接受，但新前端只调用新接口；旧接口不能继续承担“全部币种”的模糊响应。
- 不修改前端页面，不提交、不推送、不部署。
