# Ticket 02：页面局部币种、账户与交易表达

## 目标

移除全局 Active Currency，把预算账本状态放进预算页 URL；让账户与交易始终按自身币种表达，并补齐筛选、空状态、锁定状态和双金额标签。

## 必须先写的失败测试

- 桌面与移动侧栏没有币种选择器，仍按账户币种显示全家庭账户和分币种小计。
- `#/budget` 根据本设备最近预算账本或确定默认值补全 URL；显式 URL 优先；不支持或已停用参数提示并 replace；快速切换忽略迟到响应。
- 预算标题区显示“预算账本”选择器；切换只影响预算页；JPY 精度与所有预算金额同步变化。
- 无预算内账户与已有账户但无资金使用不同空状态；从空状态创建账户时预填当前预算账本币种。
- 账户页新建表单只列已启用币种，普通入口预填净资产默认币种并有“管理币种”入口。
- 有真实流水或非零余额的账户只读显示“账户币种”；真正空账户通过显式动作修改，并只列已启用币种。
- 交易页默认显示全部币种，并提供可与账户、分类、搜索组合的币种筛选。
- 外币消费显示“账户入账／商户计价”；跨币种转账显示“转出／入账”和目标账户；多币种批量选择没有未经换算的总额。

## 实现约束

- App Context 不再暴露影响多个页面的 `activeCurrency`。预算最近值只能作为无参数入口的回退，不是页面当前状态。
- URL 读写集中为可单测的纯函数；使用 hash route 时保留 query，避免 `startsWith` 判断吞掉页面子路由。
- 账户和交易主金额继续使用账户币种；原始消费金额只作辅助展示，不能参与余额、预算或收支。
- 每个新文案同时加入中文和英文，并为选择器、动态提示和双金额提供可访问名称。
- 不实现三类报表内容，不提交、不推送、不部署。
