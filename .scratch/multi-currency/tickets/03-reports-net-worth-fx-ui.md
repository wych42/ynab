# Ticket 03：三类报表、家庭净资产与汇率界面

## 目标

把报表按用户问题拆成“收支（按币种）”“投资”“家庭净资产”，修复全部币种收支缺失，并让净资产折算和汇率信息具备可复算、可分享、可解释的界面。

## 必须先写的失败测试

- 报表有三个可访问入口和独立 URL，不显示一个控制多种口径的裸币种标签。
- 收支无参数入口默认请求全部币种摘要；每个活动币种分别显示收入、支出和净流入，不显示跨币种合计；选中一个币种后显示单币种详情并把筛选写入 URL。
- 零余额且无活动的已启用币种不占摘要区域，但出现在筛选器并有空状态。
- 投资默认列出全部投资账户，按币种小计并支持币种/账户筛选，不出现收益、利润或回报率。
- 家庭净资产无参数入口取净资产默认币种和当前估值日并补全 URL；临时切换只改 URL，不写家庭设置或本地存储。
- 缺汇率时总资产、总负债、净资产和不完整历史点不被补零；原币明细与缺失清单仍显示。
- 每个账户显示原币余额、换算金额、`1 USD = ¥7.20` 方向、汇率日期和“人工汇率／欧洲央行参考汇率／无需换算”。
- 汇率缓存明细收进高级区域；默认区域显示覆盖、最后更新时间、刷新和人工覆盖。页面说明参考汇率只用于资产负债估值。

## 实现约束

- 全部币种摘要不把不同货币放在同一数值轴上；迷你趋势若保留，只提供弱化的币种内趋势。
- 净资产 URL 参数名统一使用面向用户的 `currency`，API 仍可使用 `reportingCurrency`；页面适配层负责转换。
- FX 内部 source/path 代码只能留在 API 数据和诊断区域，不直接作为用户文案。
- 图表必须有可读文字摘要；`null` 代表无法计算，不能通过 `|| 0` 或 `?? 0` 进入图形。
- 不修改并发协议，不提交、不推送、不部署。
